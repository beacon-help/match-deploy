# Welcome to your CDK TypeScript project

This is a blank project for CDK development with TypeScript.

The `cdk.json` file tells the CDK Toolkit how to execute your app.

## Useful commands

* `npm run build`   compile typescript to js
* `npm run watch`   watch for changes and compile
* `npm run test`    perform the jest unit tests
* `npx cdk deploy`  deploy this stack to your default AWS account/region
* `npx cdk diff`    compare deployed stack with current state
* `npx cdk synth`   emits the synthesized CloudFormation template

## Deploying

```shell
make deploy-stack            # dry run: checks only, nothing is deployed
make deploy-stack DEPLOY=1   # the same checks, then `cdk deploy`
```

The checks run in order and stop at the first failure: prerequisites, config,
release tag (must exist in both repos), AWS credentials (account must match `AWS_ACCOUNT_ID`), CDK bootstrap, EC2 key
pair, backend and frontend tests, synth, current stack state, and the diff
against what is deployed. Every AWS call in them is read-only.
`DEPLOY_ENV_FILE` points at an env file other than `.env`.

match-deploy decides the config version of everything it ships. The backend and
frontend are cloned at the release tag into `temp/release/`, their
`vendor/match-config` is checked out at this repo's pinned commit, and their
tests run against it: mypy and pytest for the backend, svelte-check and vitest
for the frontend. A repo pinned to a newer match-config than this one stops the
dry run, because that would be a downgrade. The tests need `uv` and `pnpm`, and
take about 1.5 minutes.

## What a deploy creates in AWS

**Dry run (`make deploy-stack`): nothing.** Every AWS call is a read. It writes
only local files: `cdk.out/` and `temp/release/`.

**Deploy (`make deploy-stack DEPLOY=1`):** one CloudFormation stack,
`MatchCdkStack`, in `{config.deploy.aws_region}`, holding exactly these resources.
The `{config.deploy.name}_` prefix names each of them.

| Resource | Name | What it is |
|---|---|---|
| EC2 instance | tag `Name={config.deploy.name}_ec2_instance` | `{config.deploy.instance_type}` (arm64), running the latest Amazon Linux 2 arm64 AMI at deploy time. Placed in the default VPC's subnet in an availability zone of `{config.deploy.aws_region}`, which auto-assigns a public IPv4 address; the address changes on stop/start. SSH key pair from `AWS_KEY_PAIR`. Root disk: 8 GiB gp2, unencrypted, deleted with the instance. User data is an empty script, so nothing is installed or started on it. |
| Security group | `{config.deploy.name}_sg` | Inbound TCP `{config.deploy.http_port}` and `{config.deploy.https_port}` from anywhere (`0.0.0.0/0`). All outbound allowed. No inbound SSH (22). |
| IAM role | generated by CloudFormation | Can be assumed by EC2. No policies attached, so the instance has no AWS permissions. |
| IAM instance profile | generated by CloudFormation | Attaches the role to the instance. |
| IAM user | generated by CloudFormation | No policies attached. Nothing uses it yet. |
| IAM access key | none | Belongs to that user. The stack does not output the secret. |
| CDK metadata | `CDKMetadata` | Records the CDK version for AWS's usage statistics. No infrastructure. |

Before creating the stack, `cdk deploy` uploads the template to the bootstrap
bucket `cdk-hnb659fds-assets-<account>-<region>`. Afterwards it writes
`outputs.json` locally, which stays empty because the stack has no outputs.

**Used, not created:** the default VPC and its subnet, the EC2 key pair, the
`CDKToolkit` bootstrap stack, and the public SSM parameter that names the latest
Amazon Linux 2 AMI. The key pair and bootstrap stack must already exist; the dry
run checks both.

**On later deploys:** the AMI is looked up again on every deploy. When AWS has
published a newer Amazon Linux 2 image, CloudFormation replaces the instance, and
its disk goes with it.

**Removing it:** `npx cdk destroy MatchCdkStack` deletes every resource in the
table, including the instance and its disk.

## Shared config (match-config)

`vendor/match-config` is a git submodule pinned to a tag. After a fresh clone:

```shell
git submodule update --init --recursive
npm install   # links and builds vendor/match-config/typescript
```

```ts
import { getConfig } from 'match-config';
```

Needs Node >= 22.12 (the package is ESM, loaded with `require()`). Local
overrides go in a gitignored `config.local.yaml`.

The `deploy` section holds the shared values: resource-name prefix (`name`), region,
release tag, backend and frontend repos, instance type and ports. `.env` keeps only
the private ones: `AWS_ACCOUNT_ID` and `AWS_KEY_PAIR`.

`release_tag` is the git tag deployed from both repos, so tag the backend and
frontend with the same name. To deploy a tag before it is set in match-config,
put it in `config.local.yaml`:

```yaml
deploy:
  release_tag: v1.0.0
```
